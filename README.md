# It's Almost Night

Одиночная FPS/defense-игра на C++20 и raylib. Игрок исследует процедурный
ландшафт, добывает дерево и камень, строит многоэтажную базу вокруг Ядра и
защищает её от ночных волн противников.

Проект находится в активной разработке. Текущая версия уже содержит полный
цикл добычи, строительства, улучшений, производства ресурсов и боевых волн.

## Возможности

- фиксированная симуляция с частотой 60 тиков в секунду;
- обычные здания и модульные конструкции: платформы 2×2, стены и рампы;
- этажи высотой четыре клетки и структурное разрушение;
- дерево, камень и кристаллы, ручная и автоматическая добыча;
- восемь уровней зданий, ремонт, продажа и сравнение характеристик;
- семь типов врагов с уникальными анимированными моделями, локальным избеганием
  и атаками построек;
- бесконечные волны с ростом состава, здоровья, урона и повторными боссами;
- групповой spawn и лимит 512 одновременно активных врагов;
- турели, пушки, ловушки, ружьё, кирка и бомбы;
- flow field, spatial hash и инстансинг для больших волн;
- процедурные руины, каменные заставы, лагеря лесорубов и дворы с колодцами;
- динамическое освещение, тени, AO, туман, небо и постобработка;
- pixel smoothing с регулируемым размером пикселя;
- world-space health bar и эффекты попаданий, строительства и улучшения;
- raygui-панель графических настроек с живым предпросмотром;
- звуки с пространственным затуханием.

## Требования

- CMake 3.25 или новее;
- Ninja;
- компилятор с поддержкой C++20;
- Git и доступ к сети при первой конфигурации.

CMake загружает закреплённые версии raylib 6.0 и raygui. Raylib собирается с
`SUPPORT_GPU_SKINNING=ON`, необходимым для анимированных моделей противников.
`nlohmann_json` используется из системы либо также загружается автоматически.

## Сборка и запуск

```bash
cmake --preset debug
cmake --build --preset debug
ctest --preset debug
./build/debug/its_almost_night
```

Release-сборка:

```bash
cmake --preset release
cmake --build --preset release
```

Профилирование реального геймплея:

```bash
cmake --preset profile
cmake --build --preset profile
./build/profile/its_almost_night
```

Preset `profile` использует Release (`-O3 -DNDEBUG`) и дополнительно сохраняет
символы функций для Instruments. В игре `Shift+F10` открывает
телеметрию стадий кадра. `AVG` показывает постоянную нагрузку, `PEAK` — недавний
скачок. Если CPU-проходы быстрые, а время уходит в `PRESENT/WAIT`, профилировать
нужно GPU через Instruments → Metal System Trace.

В настройках → «Графика» переключатель «Запись performance log» включает и
останавливает запись без перезапуска игры. При включённом логировании игра
записывает покадровую телеметрию в
`performance_logs/session_*.csv`. Лог содержит режим матча/строительства,
число врагов и построек, полное время кадра и время каждой стадии. Запись
буферизована и закрывается при нормальном выходе из игры.

Для сводки по игровым кадрам:

```bash
python3 tools/analyze_performance.py performance_logs/session_*.csv --target-fps 200
```

Скрипт показывает p50/p95/p99, стадии, сильнее всего замедляющие худшие 5%
кадров, свежие GPU-замеры, нагрузку сцены и сравнение кадров с наведением на
разные объекты. `--output report.txt` сохраняет отчёт. `--all-states` включает
меню и паузу; по умолчанию они исключены вместе с первыми двумя секундами
запуска. В новых логах `frame_interval_ms` учитывает также запись лога и прочую
работу между кадрами; `frame_ms` измеряет только сам кадр и используется для
поиска дорогих стадий. `gpu_shadow_ms`, `gpu_selection_ms` и `gpu_scene_ms`
показывают тени, маску наведения и основную сцену. Эти части измеряются
поочерёдно на редких кадрах и не складываются с общим `gpu_world_ms` из
той же строки CSV. `gpu_terrain_ms`, `gpu_objects_ms`,
`gpu_environment_ms` и `gpu_overlays_ms` дополнительно делят основную сцену.
На macOS драйвер может переносить работу между GPU-запросами: времена этих
подпроходов нельзя складывать или считать точной стоимостью отдельной части.
Для сравнения сборок используйте общее `gpu_world_ms` и `gpu_postprocess_ms`.
Значения GPU приходят асинхронно и не обязаны относиться к тому же кадру CSV.
Колонки `objects_*_ms` детализируют CPU-время внутри `world_objects_ms`:
декорации/подготовка, ресурсы, пакеты камней и деревьев, сундуки/ориентиры,
монеты/опыт, разрушенные ресурсы, постройки, снаряды/порталы, враги и трава.
Это время отправки команд, включая возможное ожидание драйвера, а не
изолированные GPU-замеры. Участки измеряются без дополнительных flush/finish;
в начале кадра значения обнуляются. Анализатор показывает три самых долгих
участка объектов для каждого из худших кадров. Они вложены в общие стадии,
поэтому их нельзя прибавлять к `world_objects_ms`.

`selection_kind`:
0 — нет цели, 1 — ресурс, 2 — враг, 3 — постройка, 4 — сундук,
5 — модульная постройка, 6 — испытание, 7 — ориентир, 8 — добыча,
9 — предпросмотр постройки.

загружаются с прежними значениями.

### Общий лимит построек

Добывалки, орудия, здания поддержки и ловушки используют общий лимит экземпляров:
**3 на первом уровне ядра, затем +2 за каждый уровень** (до 17 на восьмом).
Ядро, стены, ворота, платформы и пандусы этот лимит не занимают. Продажа или
уничтожение здания немедленно освобождает место. В Godmode лимит отключён.
Лимит типов чертежей в слотах сооружений — отдельная существующая механика.

«Том расширения» увеличивает лимит, занимает обычный слот тома и сохраняет
дробную силу редкости: используется `floor` накопленной суммы, без вероятностей.
Шрайн построек может дать +1 место; магазин дополнительно предлагает отдельную
покупку «+1 постройка». Эти два бонуса не занимают слотов, суммируются с томом и
действуют до конца забега. Покупка +1 всегда даёт ровно одно место и не выпадает
при повышении уровня. Старые сохранения сохраняют все существующие здания,
даже если база превышает новый лимит; новые постройки требуют свободного места.

### Магазин между волнами

После обычной волны и выбора наград за уровни открывается магазин: четыре
предложения из того же пула карточек. Покупки и растущие по цене рероллы оплачиваются
монетами. Каждую карточку можно закрепить: её редкость и цена сохраняются между
волнами. Покупка всех четырёх предложений бесплатно обновляет витрину. Лимит томов
и уникальность открываемых чертежей сохраняются. Во время магазина мир стоит на паузе;
«Продолжить» возвращает к подготовке. `1`–`4` покупают карточки, `R` обновляет витрину.

### Строительство

- `1` — Ядро;
- `2` — стена;
- `3` — турель;
- `4` — кристальная шахта;
- `5` — пушка;
- `6` — замедляющая ловушка;
- `7` — ворота;
- `8` — лесопилка;
- `9` — каменоломня;
- удерживать `Tab` и направить мышь — выбрать режим зданий или фундаментов;
- `0` — быстро переключить режим фундаментов;
- в режиме фундаментов hotbar переключается на модульные элементы:
  `1` — фундамент (20 дерева, 5 камня), `2` — этажная платформа
  (20 дерева, 5 камня), `3` — стена (5 дерева, 10 камня),
  `4` — рампа (16 дерева, 4 камня);
- `V` в режиме фундаментов — следующий модульный элемент;
- колесо мыши — повернуть обычное здание, модульную стену или рампу;
- рампа — смотреть на платформу: ребро выбирается по направлению
  взгляда и удерживается в расширенной зоне, колесо переключает
  соседнее;
- фундамент ставится только на terrain, без привязки к рёбрам;
- этажная платформа ставится только над существующей платформой;
  на верхних этажах свободное ребро платформы или верх рампы
  позволяют продолжить текущий этаж;
- удерживать `ЛКМ` — протянуть линию поддерживаемых элементов;
- `ПКМ` — отменить строительство.

`V` переключает модульные элементы только в режиме стройки; при выбранных бомбах пополняет запас. Оружие, топор и кирка улучшаются карточками до уровня ядра. Подробнее: [уровни оружия](docs/WEAPON_CARD_LEVELS.md).

### Графика и отладка

Отладочные клавиши по умолчанию отключены. Включить или отключить их все
можно в `F2 → Игра → Отладочные клавиши`. Настройка сохраняется между запусками:
она управляет читами, спавном врагов, выдачей предметов и карточек, отладочными
панелями, изменением времени, техническими визуализациями и графическими
хоткеями. Обычное управление и обратная связь на `F3` продолжают работать.

| Клавиша | Действие |
|---|---|
| `F2` | настройки игрока: графика, звук, управление, игра; во время забега ставит игру на паузу |
| `F3` | скриншот и подпись для обратной связи; игра встаёт на паузу |
| `Ctrl + F2` | расширенная панель для дебага: цвет, `STYLE LAB`, модель оружия и технические параметры |
| `F1` | просмотр shadow map |
| `Ctrl + F3`, `F4`–`F9` | тени, туман, postprocess, частицы, blob shadows, bloom и SSAO |
| `Shift+F7` | изменить силу AO |
| `F10` | качество графики |
| `Shift+F10` | показать телеметрию производительности |
| `F11` / `Shift+F11` | увеличить/уменьшить размер пикселя мира |
| `F12` / `Shift+F12` | world shader / процедурное небо |
| `Ctrl+F8` | показать коллайдеры |
| `H`, `L` | flow field / spatial hash |
| `J` | скрыть только нижний HUD |
| `B` | меню создания от 1 до 1000 врагов |
| `O` | god mode |
| `Ctrl+F6` | terrain wireframe |
| `Ctrl+F7`, `Ctrl+F9` | регенерация terrain |
| `Ctrl+F10` | структурное разрушение |
| `Ctrl+F11` | очистить модульные конструкции |

Дополнительные debug-клавиши находятся в
[AppInput.cpp](src/app/AppInput.cpp).

## Архитектура

```text
app            окно, ввод, frame loop, presentation orchestration
game           Simulation, команды, snapshot и игровые события
buildings      здания, сетка, платформы и структурная поддержка
combat         оружие, турели, пушки, ловушки и бомбы
enemies        AI, анимационные состояния и capsule separation
world          terrain, коллизии, карта и spatial hash
graphics       модели, terrain, shaders и render passes
presentation   краткоживущие визуальные состояния
ui             HUD, world-space панели и общий текст
audio          звуки и пространственное затухание
```

Симуляция не зависит от raylib и файлового ввода-вывода. `App` передаёт ей
команды и читает `SimulationSnapshot` и `GameEvent`. Баланс и параметры мира
загружаются из JSON перед созданием симуляции.

## Данные и ассеты

- `assets/data` — баланс врагов, волн, зданий, экономики и мира;
- `assets/maps` — стартовая карта и точки появления;
- `assets/models` — здания, окружение и анимированные враги;
- `assets/shaders` — world, terrain, selection и postprocess shaders;
- `assets/audio` — игровые звуки и лицензии;
- `assets/ui` — шрифт, панели и иконки ресурсов.

Сторонние лицензии и уведомления хранятся рядом с соответствующими ассетами.
На русском языке цифры и клавиши сохраняют исходный шрифт; кириллица
заголовков использует Rubik One. Подробности: [шрифты UI](docs/UI_FONTS.md).

## Проверки и git

Все тесты собираются в `ian_tests`. Перед коммитом выполняются Debug-сборка,
тесты и `git diff --check`; для рискованных изменений также используется
sanitizer preset.

Изменения ведутся небольшими тематическими коммитами. Временные рендеры,
сборочные каталоги и локальные `.DS_Store` в репозиторий не добавляются.

### Обратная связь тестеров

Нажмите **F3** в нужный момент: игра остановится, скриншот появится в рамке,
под ним можно написать комментарий (до 1200 символов, включая русский текст).
Нажмите **Сохранить** или **Ctrl / Cmd + Enter**, затем **Готово** для продолжения.
**Esc / Отмена** закрывает несохранённый черновик. Настройки доступны через меню
паузы (**Esc → Settings**), **F2** и главное меню.

Отправьте разработчику папку **feedback** рядом с игрой (кнопка **Открыть папку**
появляется после сохранения). Внутри каждого отчёта: чистый `screenshot.png`,
подпись `comment.txt` в UTF-8 и `context.json` с версией, сидом, ночью,
координатами и техническим состоянием. Отчёты хранятся локально и автоматически
никуда не отправляются. Папку можно перенести или заархивировать целиком.

### Персонажи для тестирования

В новых забегах доступны четыре персонажа: Дровосек (ближний бой и дерево),
Стрелок (дальнее оружие), Механик (постройки и дешёвый ремонт), Старатель
(ручная добыча и производство). У каждого есть постоянная пассивка, небольшой
штраф и прирост характеристик/HP за уровень. Все четыре открыты сразу.
Топор и кирка есть у всех; стартовые чертежи и предметы показаны в выборе класса.
Подробные числа и совместимость сохранений: [BASIC_CHARACTERS.md](docs/BASIC_CHARACTERS.md).
