# Agent Workflow

## Перед изменением

1. Прочитать `INSTRUCTION.md`.
2. Определить один ограниченный результат и acceptance criteria.
3. Не менять публичные интерфейсы соседних систем без согласования.

## Во время изменения

- Не добавлять зависимости без ADR.
- Не подавлять warnings.
- Не оставлять TODO вместо результата.
- Не форматировать несвязанные файлы.
- Не смешивать новую функцию и несвязанный рефакторинг.
- Не создавать абстракцию для одного использования.

## Перед завершением

```bash
cmake --preset debug
cmake --build --preset debug
ctest --preset debug
git diff --check
```

Для изменений в памяти, lifetime, контейнерах или указателях дополнительно:

```bash
cmake --preset sanitizers
cmake --build --preset sanitizers
ctest --preset sanitizers
```

## Git

- После каждого завершённого результата создать тематический коммит.
- Перед `git add` проверить `git status --short` и ignore-правила.
- Не добавлять `build/`, `tmp/`, `.DS_Store`, логи и debug screenshots.
- Не перезаписывать и не откатывать чужие незавершённые изменения.
- Не использовать destructive-команды (`reset --hard`, `checkout --`) без
  явного запроса.
- В сообщении коммита кратко указать тип и результат:
  `feat:`, `fix:`, `refactor:`, `docs:`, `test:` или `chore:`.

В отчёте указать изменённые публичные интерфейсы, проверки, ограничения и hash
созданного коммита.

## Формат задачи

```text
Цель
Контекст
Разрешённые файлы
Запрещённые изменения
Публичный интерфейс
Acceptance criteria
Команды сборки и тестов
Ожидаемый результат
```
