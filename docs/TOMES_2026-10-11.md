# Run tomes

The final passive pool uses a central tome catalog: 22 active entries plus five
reserved legacy metadata entries. Damage, health, production, quantity,
bounce, pierce, crit, duration, size, knockback and poison share one slot pool.
Weapon acquisitions, building blueprints, cannon specializations and card-control
perks retain their existing rules. Stable RunUpgradeEffect IDs are unchanged.

A normal run starts with four distinct tome slots. Acquiring an owned tome levels
it without using another slot; existing rarity gains and per-upgrade level/power
limits remain unchanged. Once full, offer generation and rerolls exclude new
tomes. Selection revalidates stale offers. An exhausted card pool closes the
chooser, and valid one- or two-card offers can be saved and resumed.

Meta shop `tome_slots` adds one slot per rank, maximum two ranks (six total), for
10 and 15 silver. Purchases apply to the next run. Older profiles and suspended
runs default to zero additional slots. Oversized old/debug inventories keep all
bonuses; new normal acquisitions remain gated. Debug grants bypass distinct slot
limits and existing bulk grants remain unlimited.

GameUi caches colored book artwork using the existing stat emblems. Offers,
Shift+F5 and the HUD resolve the same textures. The HUD shows empty slots and a
used/available counter; offers show a localized tome counter. Loot textures remain
separate. Book textures are created once and released with GameUi.

Public additions: RunTomeDefinition / RunTomeDefinitions / runTomeDefinition,
runTomeCount, runTomeSlotLimit, BaseRunTomeSlots / MaximumRunTomeSlots,
MetaShopUpgrade::TomeSlots, MetaRunBonuses::additionalTomeSlots,
SimulationSnapshot::tomeCount / tomeSlotLimit. Former hammer metadata names have
source-compatible aliases. Save enum values were not reordered; meta bonuses add
an optional `additionalTomeSlots` field, and shop persistence uses its string ID.

## Final pool and shared stats

Bomb Supply, Cluster Payload, Turret Shrapnel and Trap Pulse are weapon perks,
with their existing weapon-ownership requirements and effects. They no longer
occupy tome slots. Daylight and Overkill leave normal offers; explicit debug
access and saved bonuses remain intact. Legacy separate defense damage/speed
cards also leave normal offers. There are 44 active upgrade definitions overall:
22 tomes and 22 blueprint, specialization or weapon-perk cards.

Might adds +10% player damage and +12% defense damage per common rarity power.
Rapid adds +15% player weapon speed and +10% defense speed. Existing rarity
multipliers apply to both halves. Reserved defense power IDs store the defense
half without inventing or reordering save IDs. Old separate player/defense levels
share one displayed slot and their summed level; old powers are not retroactively
boosted. Availability respects this shared level and original per-stat power caps.

Gathering is active again and adds +15% axe/pickaxe speed per rarity power.
Rapid affects combat weapons, not gathering tools. A separate persisted tool
baseline keeps class and historical tool speed intact: absent `toolAttackSpeed`
in older JSON defaults to saved `playerAttackSpeed`. New runs clear both baselines.
Public additions for this pass: `runTomeLevel`, `legacyRunTomeUpgrade`,
`RunUpgradeStats::toolAttackSpeed`, `SuspendedRunState::toolAttackSpeedMultiplier`.

The HUD has square cells, equal horizontal/vertical gaps and no used/available
counter. Cell pitch increased from 44 to 52.8 pixels; the row moved from y=64
to y=82. Empty-slot plus signs center using measured text dimensions. Offers
retain capacity information; shared-stat descriptions show both rarity-scaled
bonuses. HUD, offer badges and inventory resolve merged legacy levels.
