`EndDrawing` включает swap buffers, frame accounting, native events и иногда capture/automation. CPU wall time не отделяет активную работу потока от ожидания драйвера/ОС. Существующие асинхронные GPU subpass queries могут захватывать deferred driver work и не дают точной суммы стоимости проходов. Длительность recorder между кадрами мала: median 0.01 ms, p99 0.02 ms.

## Добавленная диагностика

Ограниченный результат этого прохода — измерить активную работу CPU внутри `EndDrawing` и отдельно уже существующую отправку финального render batch. Порядок отрисовки, pacing, число draw calls и качество не меняются. Никаких новых `glFinish`, ожиданий GPU или дополнительных flush не добавлено.

Четыре столбца дописаны в конец CSV, прежние IDs/порядок сохранены:

- `final_batch_submission_ms`: wall time существующего `rlDrawRenderBatchActive()` перед pacing.
- `present_thread_cpu_ms`: разница `CLOCK_THREAD_CPUTIME_ID` перед и после `EndDrawing`; учитывает user + kernel CPU time именно текущего потока, исключает сон/descheduling.
- `present_not_running_ms`: `max(0, present_swap_ms - present_thread_cpu_ms)`.
- `present_thread_cpu_valid`: валидность пары CPU-clock samples.

Показания сбрасываются в начале каждого кадра; замеры выполняются только при включённом performance log. Если thread CPU clock отсутствует или не прочитан, valid=0; нули нельзя трактовать как отсутствие CPU work. macOS/Linux используют POSIX thread clock. В текущем Windows fallback эти два показания недоступны и valid=0.

Если 30 ms `EndDrawing` содержит только 0.5 ms CPU work, остальное — время без выполнения потока. Это может быть driver/GPU blocking, swap/event waiting или descheduling; **поля не различают эти причины между собой**. Если CPU time близок к wall time, поток действительно работал, включая возможный busy wait. Собственный `paceFrame()` остаётся за пределами этих показаний.

Публичные структуры `RendererPerformanceStats` и `PerformanceFrameRecord` расширены только диагностическими значениями. `App` передаёт их в recorder. Анализатор рабочего дерева печатает отдельный блок только по valid samples и добавляет CPU/not-running detail к худшим кадрам; старые CSV поддерживаются.

## Проверки

- Debug и Release собраны без новых compiler warnings; прежнее configure warning raylib о deprecated OpenGL на macOS сохраняется.
- Полный Debug прогон: первоначально 15/17. Новая проверка ошибочно предполагала, что raylib limiter спит; в этой сборке `SUPPORT_BUSY_WAIT_LOOP=ON`, он занимает CPU. Проверка исправлена: валидирует длительность/accounting при любом типе limiter и сброс при выключении логирования. Повтор обеих упавших проверок: новая прошла, прежний `ian_run_menus_smoke` снова падает с `native window retains upgrade names after the SDF cache warms under scissor`. Итог текущих проверок **16/17**, единственный оставшийся сбой существовал до прохода.
- Release graphics smoke и render performance smoke: **2/2 passed**. Новый regression проверяет nonnegative finite values, CPU + not-running accounting и отсутствие старых показаний после отключения логирования. Pixel parity неба и viewmodel также проходят.
- CSV round-trip: **138 уникальных столбцов**, число headers/values совпадает; четыре новых значения корректно сериализуются. Анализатор исключает invalid CPU samples, даже если в них записаны ненулевые значения.
- Python compile и обработка прежних CSV: успешно. `git diff --check`: успешно.
- Sanitizer graphics smoke и render performance smoke: **2/2 passed**, ошибок ASan/UBSan нет. Полный sanitizer набор не повторялся: lifetime, контейнеры и владение памятью не менялись.

Измерения выполняются на текущем рабочем дереве с предшествующими незавершёнными правками. Коммит включает только собственную диагностику, regression и этот отчёт. Анализатор ранее был незакоммиченным файлом; его изменения остаются в рабочем дереве. Логи и временные CSV-проверки не включаются в Git.

Release `build/release/its_almost_night` содержит новую диагностику. Следующая короткая запись с активным окном позволит оценить CPU/not-running составляющие просадок. Этот проход сам по себе не увеличивает FPS и не устраняет стартовую паузу.
