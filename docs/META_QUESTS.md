# Постоянные квесты

## Основа

В Megabonk квесты автоматически отслеживают накопительные достижения, цели
за один забег и требования к конкретной сборке. Выполнение открывает контент
и может дать серебро; для части контента после выполнения требуется покупка.
Категории помогают просматривать условия и завершённые цели.
Источники: [Quests](https://megabonk.wiki/wiki/Quests),
[таблица условий и наград](https://megabonk.fandom.com/wiki/Quests),
[покупки разблокировок](https://megabonk.org/guides/unlocks/).

Fortbonk использует эти принципы с целями под сооружения. Конкретные цели,
цены и пороги ниже — баланс Fortbonk. Экран QUESTS подключён к этой системе.
Отдельный магазин и эффекты будущих метаулучшений добавляются отдельно.

## Каталог

`assets/data/meta_quests.json` содержит 36 определений. Есть категории
`characters`, `buildings`, `weapons`, `upgrades`, `items`, `general`,
`challenges`, `cosmetics`. Категории без соответствующих квестов
можно скрывать в будущем интерфейсе.

- Старые условия открытия четырёх классов сохранены.
- Общие убийства и убийства конкретным сооружением: пулемётная турель,
  пушка, магическая турель, шипованная ловушка.
- Строительство, улучшение зданий, ремонт инженером.
- Уровни карточек и параметры сборки: урон сооружений, скорострельность,
  рикошеты, кассетные взрывы, здоровье, уровень игрока.
- Сундуки, предметы, ресурсы, золото и испытания.
- Победа без открытия сундуков — составное условие за один забег.
- 10/20/30 завершённых квестов дают право купить `meta.refresh`,
  `meta.skip`, `meta.banish` за 10/15/20 серебра соответственно.

Эти три ключа пока представляют права на покупку в системе. Купить открытую
разблокировку можно в деталях квеста. Применение эффектов к выбору карточек
добавляется отдельно. Существующие
карточки и предметы остаются доступными по текущим правилам игры.

Награды: 1–4 серебра, всего 64 за новый профиль. XP не выдаётся.

## Условия и жизненный цикл

`QuestSystem` не зависит от графики. `QuestGameplayTracker` переводит события
симуляции и изменения параметров сборки в сигналы квестов.

- `lifetime`: прогресс сохраняется между забегами.
- `run`: незавершённые цели обнуляются при новом забеге или рестарте.
  Завершённые цели остаются завершёнными навсегда.
- `at_least`: достичь порога; `at_most`: ограничение внутри одного забега.
  Все условия одной цели должны выполняться одновременно. Для ограничений
  нужен положительный рубеж, например `stage_clears >= 1` вместе с
  `chests_opened <= 0`.
- `subject`: фильтр сооружения, типа врага или карточки; `playerClass`:
  фильтр класса. Отсутствующий фильтр принимает любые подходящие события.
- `prerequisites`: все перечисленные квесты должны быть завершены.
  До этого прогресс может накапливаться. Цепочки разрешаются автоматически;
  циклы и неизвестные ссылки отклоняются при загрузке.
- Убийства считаются по `EnemyKilled`. Попадания, частицы и вспышки не
  считаются убийствами. Ресурсы считаются по `ResourceGranted`, золото —
  по фактическому подбору `CoinCollected`.
- Параметры уровня, HP, множителя урона и уровней карточек учитываются
  как максимум, а не сумма наблюдений. Уровень карточки — число её выборов,
  независимо от редкости выбранной карточки.
- Завершение испытания имеет отдельное событие `ChallengeCompleted`.
- Sandbox полностью исключён из накопления прогресса и выдачи наград.

Проверки выполняются пакетами событий, поэтому ограничение и положительная
цель в одном пакете оцениваются вместе. Завершение выплачивает награду сразу
и только один раз. Покупка отдельно проверяет выполненное условие, баланс
и отсутствие владения, затем списывает серебро и записывает владение.

## Сохранение и совместимость

`MetaProgression` включает `QuestState`; файл профиля имеет версию 3,
секция `quests` — версию 1. Прогресс, флаги выполнения, серебро и владение
сохраняются в одном файле через временный файл и замену. Для Windows есть
восстановление из резервного файла при прерванной замене.

Профили версий 1/2 читаются. При первом `initialize` старые общие счётчики
переносятся в подходящие накопительные цели. Уже достигнутые цели отмечаются
без повторной выплаты серебра; открытые классы сохраняются. Исторические
убийства по отдельным сооружениям не восстанавливаются: таких данных раньше
не было. Новые цели начинают отслеживание с момента установки этой версии.

Начало/конец забега, победа и завершение квеста вызывают сохранение в App.
Промежуточный прогресс также сохраняется при сохранении забега и штатном
выходе. Аварийное завершение может потерять прогресс после последней записи.
Прогресс текущего забега сохраняется для продолжения отложенной игры.
`resumeRun` сохраняет известный прогресс. Для старых отложенных забегов
без истории квестов накопление начинается с продолжения, а условия
«не делать действие» недоступны до нового забега: неизвестная история
не считается отсутствием действий.

ID квестов и разблокировок постоянны. Не переиспользовать ID для другой
цели. Записи неизвестных ID сохраняются для совместимости, но не входят
в счётчик завершённых квестов актуального каталога. Повреждённый каталог
отклоняется целиком; App сообщает предупреждение и использует встроенный
каталог с теми же определениями.

## Экран квестов

В главном меню кнопка QUESTS открывает отдельный экран:

- Все цели и восемь категорий со счётчиками выполнения.
- Прокручиваемый список, награда серебром и отметки завершения.
- Выбор строки показывает описание, срок цели, требования, награду
  и получаемую разблокировку.
- Флажок «выполненные в конце», выбор мышью или стрелками.
- Tab/Shift+Tab переключают категорию; колесо и ползунок прокручивают
  список; X/Esc закрывают экран.
- Покупка доступна после выполнения цели при достаточном количестве
  серебра. Повторная покупка исключена; App сразу сохраняет изменение.
- Поддержаны английский и русский, масштабирование под разрешение экрана.

Блок на главном экране берёт четыре незавершённых квеста из того же
каталога и сохранения. Сначала идут доступные цели с наибольшим процентом
выполнения; равный прогресс сохраняет порядок каталога. Завершённые цели,
цели с невыполненными требованиями и проваленные ограничения текущего
забега исключены из рекомендаций. После завершения квест сразу уступает
место следующему. Клик по краткой карточке открывает его детали.
Полный список по умолчанию использует такой же порядок; выполненные
остаются в конце. Запреты вроде «не открывать сундуки» не добавляют
искусственные 50% прогресса до начала выполнения положительной цели.

Отрисовка и состояние списка находятся в `ui/QuestMenu.*`. `drawQuestMenu`
принимает явные размеры окна и ввод; `QuestMenuResult` сообщает закрытие,
покупку и взаимодействие для сохранения и звука в App.

## API квестов

```cpp
QuestSystem quests(loadQuestDefinitions("assets/data/meta_quests.json"));
quests.initialize(profile);
auto rows = quests.statuses(profile); // ближайшие доступные сначала
auto featured = quests.recommendedStatuses(profile); // до четырёх незавершённых
auto summary = quests.categoryProgress(profile, QuestCategory::Buildings);
auto purchase = quests.purchaseUnlock(profile, "meta.refresh");
bool owned = quests.ownsUnlock(profile, "meta.refresh");
```

`QuestStatus` содержит определение, прогресс каждого условия, общую долю,
выполнение требований, факт завершения, доступность разблокировки и владение.
Указатель на определение действителен пока существует `QuestSystem`.
После покупки вызывающая сторона должна сохранить изменённый профиль.

Новые типы событий можно передавать напрямую через `QuestSignal`; неизвестные
метрики, отрицательные и нечисловые значения игнорируются. Сигналы изменения
статистики отправляются только при изменении значений. Подписки по метрикам
избегают полного обхода каталога на каждом кадре.
