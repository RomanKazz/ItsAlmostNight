# Автоматический боевой полигон

Запуск из корня проекта:

```sh
python3 tools/run_balance_lab.py --open
```

На macOS можно открыть `tools/RunBalanceLab.command` двойным щелчком.
Инструмент собирает только Release-target `ian_balance_lab`, прогоняет
матрицу и открывает локальный HTML с фильтрами. Окно игры и сохранения
не используются. Баланс автоматически не меняется.

Результаты каждого запуска лежат в отдельной папке `output/balance_lab/`:

- `report.html` — таблица с выбором уровня, ситуации, бонусов и сортировки;
- `raw.csv` — каждый отдельный прогон;
- `summary.md` — короткая таблица для уровня 4 и плотной толпы;
- `metadata.json` — Git revision/dirty, отпечатки исходников и бинарника, параметры;
- `config/` — копия шести JSON, использованных в прогоне.

Первый полный отчёт: `output/balance_lab/current/report.html`.
Повторение и быстрая проверка:

```sh
python3 tools/run_balance_lab.py --seconds 30 --seeds 3
python3 tools/run_balance_lab.py --no-build --seconds 10 --seeds 1
python3 tools/run_balance_lab.py --csv output/balance_lab/current/raw.csv --output /tmp/balance-report
```

`--no-build` явно использует уже собранный бинарник. После изменения
боевого кода или формул нужен обычный запуск со сборкой. HTML полностью
локальный, без сетевых библиотек и установки Python-пакетов.

## Матрица и сравнимость

Текущая полная матрица: 2628 строк (2592 боевых случая и 36 пустых линий).

12 типов: турель, арбалет, пушка, катапульта, огнемёт, ракетница, тесла,
лазер, мортира, шипы, замедляющая ловушка, ветродуй. Уровни 1/4/8.
Четыре ситуации: один Heavy, 32 Basic в плотной группе, 12 Fast
разреженно, 12 Flying. Три воспроизводимые раскладки по умолчанию.
Катапульта и мортира поражают только наземных врагов, включая взрывы,
пробивание и рикошеты. Ветродуй отталкивает также Flying, но не босса;
сохраняются сопротивление отталкиванию и проверка высоты поверхности.
Старые отчёты, созданные до изменения этих правил, нужно пересчитать.

Пресеты усилений содержат ровно четыре обычных карточки:

| Пресет | Вложение |
|---|---|
| base | Нет бонусов, отдельная база сравнения |
| damage_rate | 2 Damage + 2 AttackSpeed (их реальные бонусы обороне) |
| quantity | 4 ProjectileCount |
| quantity_bounce_pierce | 2 ProjectileCount + 1 Bounces + 1 Pierce |
| bounces | 4 Bounces |
| pierce | 4 Pierce |

Они используют `defenseAttackCardModifiers()` и игровую совместимость
статов, а не отдельную копию формул. Число применимых карточек видно
рядом с результатом: набор 0/4 для огнемёта не считается равноценным
его сильному билду. Дробная система статов/floor не менялась.

Один экземпляр оружия стоит в (0,0), ядро в (0,6). Группы пополняются
после убийства или прорыва следующим тиком: сильное оружие может убить
больше врагов. Прорыв — пересечение Z=4 либо начало атаки ядра;
удаление прорвавшегося врага не считается убийством. Это непрерывная
нагрузка с поддержанием численности, а не фиксированный бюджет ночи.
Поэтому разность прорывов с пустой линией — диагностический показатель,
а не точная оценка предотвращённого урона: количество новых врагов
зависит от результатов предыдущих атак.

AI видит только ядро: орудие не перекрывает дорогу и не получает урон.
Так изолируется оружие от его прочности. Применяются настоящие EnemySystem,
TowerSystem, CannonSystem и TrapSystem: наведение, полёт, столкновения,
отскоки, пробитие, взрывы, цепи, лазерный фокус, горение и контроль.
Урон каждого тика дополнительно сверяется с потерей HP всех целей.
Равенство spawned = killed + leaked + alive проверяется для каждого прогона.

HP умножаются на `enemyWaveHealthGrowth(уровень)`, но модификаторы
композиции ночей, elite, overtime и босс отсутствуют. Обычные игровые
JSON читаются с ошибкой при отсутствии/повреждении — скрытого fallback
на defaults нет. HP в отчёте умножены на 10, как отображаемый урон в игре.

Стоимость дерева, камня и кристаллов выводится отдельно. Это базовая
цена первой копии, без платформ и роста стоимости повторных построек.
Ресурсы не суммируются произвольным курсом; DPS/«общая цена» не выводится.

## Исторический первый отчёт до настройки томов

Первый запуск: 1764 строки — 1728 боевых случаев и 36 пустых линий.
Повтор всей матрицы дал побайтно одинаковый CSV:
`82002388e046864dd87125b9f1a3ea3d3ab651b2ea9a2a284b65c150850d6585`.

В первом отчёте, уровень 4 / плотная толпа, среднее по трём
раскладкам: комбинированный пресет повышает фактический DPS турели
22.5 → 196.9 HP/с (8.75×), пушки 189.0 → 519.7 (2.75×),
арбалета 55.3 → 271.7 (4.91×). Огнемёт остаётся 164.0 HP/с,
поскольку все четыре карточки этого пресета с ним несовместимы.
Это повод изучить различие масштабирования, а не готовый рейтинг башен.

При интерпретации учитываются отдельно одиночная цель/толпа/воздух,
прорывы, диапазон между раскладками и применимость вложений.
Нулевой DPS замедления или отталкивания не означает бесполезность.
Предметы, шрайны, классы, мета, powerup, высоты, разрушение базы и ремонт
не участвуют. Стены, приманка, ремонтная станция и добывалки требуют
отдельного сценария экономики/выживания и здесь не ранжируются.

## Интерфейсы и проверки

Новый test-only executable `ian_balance_lab`: `--output`, `--data`,
`--seconds 1..120`, `--seeds 1..8`, `--self-test`, `--help`.
Сам инструмент не меняет production API, настройки, сохранения или баланс.
Последующая настройка боевого баланса описана в `DEFENSE_TOME_BALANCE.md`;
для неё старый отчёт не считается актуальным.
Python 3 нужен для отчёта; C++ executable может отдельно выдавать CSV.

CTest `ian_balance_lab_checks` проверяет повторяемость реального боя,
эффект дополнительных снарядов, отсутствие бонуса от несовместимых
карточек, воздушную невосприимчивость ветродуя и отдельный учёт замедления.
`ian_balance_report_checks` (когда найден Python) проверяет расчёт роста,
нулевой DPS, соответствие раскладок и целостность исходных строк.
Скрипт таблицы дополнительно проверен исполнением фильтров уровня,
ситуации, бонусов и сортировки. Визуальная проверка в браузере недоступна
в текущем сеансе; сравнение данных и функциональные проверки выполнены.

Финальная проверка: Debug и Release собраны. Все 38 тестов Debug и все
38 тестов ASan/UBSan прошли без пропусков (CPU/native suites запущены
раздельно; добавленная Python-проверка также выполнена в обоих presets).
Новые C++ файлы собраны без предупреждений. Проверены ошибка числового
аргумента, shell-синтаксис launcher и `git diff --check`.
